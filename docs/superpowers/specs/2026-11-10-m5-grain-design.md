# M5 — Grain: design

Milestone 5 of [the OpenFilm design](2026-11-08-film-emulator-design.md). Builds on M4
([design](2026-11-09-m4-halation-bloom-sharpness-design.md)): colour, halation, bloom and
sharpness run on Metal in real time at UHD (≈19–20 ms all-on on the M4 Pro), with the CPU path as
reference.

## Goal

Add physically driven film grain to both the negative and the print, matched to each stock's
datasheet rms granularity, scaled by film format, varying every frame, real time at UHD in Preview
and exact in Full.

## Decisions (agreed with the user)

| Topic | Decision |
|---|---|
| Success bar | Grain strength judged against the datasheet diffuse rms granularity (48 µm aperture), per layer |
| Where | Negative grain (5219-type, per layer, on negative density) and print grain (2383-type, per layer, on print density) |
| Quality | **Full** (renders): per-pixel Boolean-model dye-cloud simulation. **Preview** (playback, real time at UHD): samples pre-made grain plates generated by the Full simulation. Both have the same strength and texture |
| Controls | Grain Enable (on), Amount 0–3 (1), Size 0.5–2 (1), Quality Preview/Full (Preview) |
| Randomness | Seeded from frame time and layer: every frame differs, every render is identical. No user seed |
| Mean | Grain preserves mean density — it never shifts the grade |
| Off = M4 | Grain off, or Amount 0, gives output identical to M4 |

Out of scope: push/pull and its effect on grain (M6); more stocks (M7); grain on negative-scan or
print-scan outputs (later output modes); gate weave, flicker, dust.

## Pipeline

```
… → develop → negative edge effect
  → NEGATIVE GRAIN (per layer, on density D_c)
  → print expose → print sharpness (softens the negative's grain, as physically)
  → print develop
  → PRINT GRAIN (per layer, on print density)
  → finish (lutD → display matrix → encode)
```

Placing negative grain before print exposure means the print's own sharpness blurs it, as in a real
print; the print then adds its own, finer grain.

## Grain model

- **Boolean model of dye clouds.** Each layer's image is a random scatter of discs (dye clouds) of
  radius `r` and per-cloud density `d₁`, placed with a Poisson intensity `λ`. Where discs overlap
  the density saturates (coverage `p = 1 − exp(−λπr²)`). For a pixel of mean density `D`, `λ` is
  chosen so the expected density equals `D`; the grain is the deviation of the realised density
  from `D`, so the mean is preserved exactly in expectation.
- **Per layer, density-dependent.** `r(D)` varies linearly with density between two fitted values
  (low and high density) — 2 numbers per layer — and `d₁` is one number per layer.
- **Layers are independent**, so grain is slightly coloured, as on film.
- **Physical units.** `r` is in mm on the film and converted with M4's `pxPerMm` (format, image
  width, OFX render scale). Doubling the gate width halves the grain size in pixels.
- **Size** multiplies `r`; the per-cloud density is adjusted so the 48 µm rms is unchanged.
- **Amount** scales the deviation from `D`. Amount 0 adds exactly nothing.
- **Negative and print** use the same model with their own fitted parameters; print grain acts on
  print density before `lutD`.

## Full mode (renders)

- For every pixel, every frame, the GPU places the clouds in a hidden grid of cells around the
  pixel (cell contents from an integer hash of cell, layer and frame seed), and computes the
  fraction of the pixel's area each layer's clouds cover; that gives the realised density.
- Identical integer hash on CPU and GPU, so the two paths agree.
- Not real time; target ≤ 1 s per UHD frame on the M4 Pro.

## Preview mode (playback)

- **Plates.** For each stock layer and 12 density levels spanning the layer's density range, the
  Full simulation generates one 2048×2048 plate holding only the grain (deviation from that level's
  mean density), in half precision.
- **Sized to the render's pixels.** Plates are generated at the render's pixel size (format,
  resolution, render scale), so a plate pixel is exactly what Full produces for one image pixel —
  same strength, same texture.
- **Per pixel.** Read the two plate levels nearest the pixel's density and blend linearly.
- **Per frame.** Each layer gets a new random offset and one of 8 orientations (rotations ×
  mirror), seeded from frame time and layer: the grain changes every frame without visible
  repetition.
- **Caching.** A plate set is generated once per (stock, pixel size, Size) and cached; the last few
  sets are kept, like the colour tables. Generation takes a few seconds — the same "wait once"
  behaviour as a stock change. Memory ≈ 3 layers × 12 levels × 2048² × 2 bytes ≈ 300 MB per stock,
  ≈ 600 MB per set (negative + print); idle sets are purgeable.
- **Speed.** Grain adds ≤ 5 ms at UHD, so Preview with everything on stays within 24 fps
  (≤ 25 ms per frame).

## Data

- `data/stocks/kodak-5219-type.json` gains `granularity`: per layer (R, G, B) points with the same
  axes as the 7219 datasheet plot (page 4), the aperture (48 µm), measurement method (diffuse rms),
  and a `sources` entry. Dye-cloud radius starting values come from published measurements, cited
  in `sources`.
- `data/stocks/kodak-2383-type.json` gains the same from the 2383 datasheet (page 4, Status A,
  "Granularity Sigma D" scale).
- Points are digitised from the PDFs' vector paths where available, otherwise hand-read, and
  reviewed with overlay PNGs as in M2/M4. Datasheet PDFs are never committed.
- At load, x values are converted to density through the stock's own characteristic curve.
- `schema.json` extended accordingly. Fitted model parameters are derived at load time (not stored)
  and memoised per stock.

## Fitting

- The Boolean model has a closed-form autocorrelation, so the rms through a circular 48 µm
  aperture is computed analytically — no simulation is needed to fit.
- At one aperture the datasheet fixes the strength curve over density but not cloud size versus
  per-cloud density. Cloud size therefore comes from the published values; the fit chooses `d₁`
  and the low/high-density radii (within a bounded range around the published value) to match
  the curve.
- At UHD Super 35 (≈ 6.5 µm per pixel) clouds come out around one pixel; this is expected.

|---|---|---|
| Grain | Enable | on |
| | Amount | 0–3, 1 |
| | Size | 0.5–2, 1 |
| | Quality | Preview / Full, Preview |

- Quality is manual: Resolve does not reliably tell a plugin whether it is playing back or
  rendering, so the user switches to Full before rendering. The docs say so.
- None of these controls re-bake the colour tables; Size and format/resolution changes regenerate
  plates (Preview only). Non-finite values are treated as the default.
- Frame time comes from the OFX render arguments.

| Test | Pass bar |
|---|---|
| Grain off, or Amount 0 | identical to M4 (bit-exact on CPU; GPU within 1e-3) |
| Fit | model rms (48 µm aperture) within 10 % of every digitised point, per layer, negative and print |
| Measured grain (CPU Full) | flat patches at several densities, measured through a 48 µm aperture: within 15 % of the datasheet per layer; negative and print each measured in isolation |
| Mean preserved | grained flat patch keeps its mean density within 0.005 |

| Format and Size | Super 16 vs Super 35 grain size in pixels follows the gate ratio ±5 %; Size 2 doubles grain size with 48 µm rms within 10 % |

| Speed (M4 Pro, UHD, worst-case frame) | Preview all-on median ≤ 25 ms, grain ≤ 5 ms of it; Full ≤ 1 s per frame |

| In Resolve (user) | grain looks filmic and changes every frame; Super 16 coarser than Super 35; Preview and Full look the same in playback; grain off equals M4 |

## Risks

- **Cloud size is not in the datasheet.** Mitigation: published dye-cloud measurements, cited;
  Size corrects texture while strength stays matched.
- **Plate memory and generation time** (≈ 600 MB per set, a few seconds). Mitigation: cache a few
  sets, purge idle ones as M4's work sets do; generate on GPU.
- **Speed headroom.** M4 leaves ~5 ms at UHD. Mitigation: one fused grain pass per stage reading
  half-precision plates; if over budget, fuse negative grain into the print-expose pass.
- **Full-mode float edges.** Disc edges landing within float rounding of a pixel boundary can differ
  CPU vs GPU; hence the 99.9 % bar plus a statistical bar.

## Refinements from planning

Recorded when the plan was written; they make the decisions above precise without changing them.

- **Granularity axis.** The datasheet graphs plot granularity against *relative* log exposure beside
  the figure's own density curves, and tell the reader to go through those curves to find the
  granularity at a density. The digitiser does exactly that, so `granularity` is stored per layer
  as `[[density, sigmaD]...]` (not on the plot's x axis), and the stock's absolute characteristic
  curve is not involved.
- **What grains.** The model acts on the density above the layer's minimum (`D − D-min`, D-min =
  the layer curve's lowest density): base, mask and fog do not grain.
- **Size** multiplies the cloud radius and rescales the deviation by the analytic factor that keeps
  the 48 µm rms unchanged (rather than changing the per-cloud density, which must stay above the
  layer's density range).
- **Coherent plates.** All density levels of one layer's plates share one cloud realisation (per-cell
  Poisson counts by inverse CDF of the same random number, cloud positions fixed per cell), so a
  level's clouds are a subset of the next level's. Blending two levels then keeps the strength;
  independent plates would lose up to 30 % between levels. Plates tile seamlessly (cells wrap at
  the plate edge).
- **Sub-pixel clouds.** When a cloud radius is below 0.25 px (e.g. HD on Super 35), both modes draw
  each pixel's deviation from a Gaussian with the model's exact pixel-area variance, since the
  texture is then finer than a pixel and simulating each cloud would cost too much.
- **Cloud radius source.** If no published dye-cloud measurement can be found, the value is an
  assumption, marked as such in `sources` (as M4's rem-jet reflectance was).
