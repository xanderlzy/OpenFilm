# OpenFilm Milestone 1 (Scaffold) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A minimal OpenFilm OFX plugin that loads in DaVinci Resolve Studio on macOS, exposes one
real parameter (Negative → Exposure, in stops), and renders it identically on the CPU and Metal
paths. It's the skeleton every later milestone builds on.

**Architecture:** Three layers, each in its own folder. `src/core/` is plain C++ with no OFX or
Apple dependencies: image views and the CPU reference renderer. `src/metal/` holds Metal kernels
plus an Objective-C++ host class that encodes them onto a Resolve-supplied command queue.
`src/ofx/` is the thin OpenFX plugin, written with the official OFX C++ Support library. It
describes the parameters and sends each render to the Metal or CPU path. CMake builds a `.metallib`
and assembles `OpenFilm.ofx.bundle`.

**Tech Stack:** C++17, Objective-C++ (Metal host code), Metal Shading Language, CMake ≥ 3.24,
OpenFX SDK (git submodule) + its C++ Support library, doctest 2.4.11 (via FetchContent), bash.

**Spec:** `docs/superpowers/specs/2026-11-08-film-emulator-design.md`

## Global Constraints

- Licence MIT; product name **OpenFilm**; plugin identifier `org.openfilm.OpenFilm`, label `OpenFilm`, grouping `OpenFilm`.
- macOS only, arm64 + x86_64 not required (build for host arch `arm64`); deployment target macOS 12.0.
- Target host: DaVinci Resolve **Studio**. Metal GPU path + CPU path sharing the same math; CPU is the reference.
- Images: 32-bit float RGBA only (declare only `kOfxBitDepthFloat`, `kOfxImageComponentRGBA`).
- Bundle layout: `OpenFilm.ofx.bundle/Contents/{Info.plist, MacOS/OpenFilm.ofx, Resources/OpenFilm.metallib}`; install dir `/Library/OFX/Plugins`.
- `src/core/` must not include OFX, Metal or Objective-C headers.
- Code comments explain OFX/Metal plumbing for a reader who is a colorist, not a GPU programmer (one short "why" comment per non-obvious block).
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Image bounds not starting at (0,0) / render window smaller than the image** — Resolve can pass images whose bounds origin is non-zero and a render window that is a sub-rectangle; only window pixels must be written, addressed relative to each image's own bounds. (Tests in Task 1 and Task 2.)
2. **Row padding** — `rowBytes` may exceed `width * 16`; pixels must be addressed with `rowBytes`, never `width`. (Task 1, Task 2.)
3. **Scene-linear values outside 0–1** — negative and very large values (e.g. −0.5, 1e4) must pass through unclamped at 0 stops and scale exactly by 2^stops otherwise; alpha is never modified. (Task 1.)
4. **Odd frame sizes** — 1×1 and 1921×1081 must render correctly on Metal (threadgroup edge guard). (Task 2.)
5. **Missing/corrupt metallib** — if the shader library cannot load, the plugin must fail the render with a visible error message, not crash Resolve. (`MetalRenderer::isValid()` test in Task 2; error path in Task 3.)

### Task 1: Repository foundation + core CPU renderer

**Files:**
- Create: `CMakeLists.txt`, `LICENSE`, `.gitignore`, `README.md`
- Create: `src/core/image.hpp`, `src/core/render_params.hpp`, `src/core/cpu_renderer.hpp`, `src/core/cpu_renderer.cpp`
- Test: `tests/core/test_cpu_renderer.cpp`

**Interfaces:**
- Produces (namespace `openfilm`):
  - `struct ImageGeometry { int x1, y1, x2, y2; std::ptrdiff_t rowBytes; };` (OFX convention: x2/y2 exclusive)
  - `struct ImageView { float* data; ImageGeometry geom; };` `struct ConstImageView { const float* data; ImageGeometry geom; };`
  - `struct RenderWindow { int x1, y1, x2, y2; };` (exclusive x2/y2)
  - `inline float* pixelAddress(const ImageView&, int x, int y)` / `inline const float* pixelAddress(const ConstImageView&, int x, int y)`; these return `nullptr` if (x,y) is outside bounds. The address is `data + (y - y1) * rowBytes` bytes `+ (x - x1) * 4` floats.
  - `struct RenderParams { double exposureStops = 0.0; };`
  - `void renderCpu(const ConstImageView& src, const ImageView& dst, const RenderWindow& win, const RenderParams& p);` writes only window pixels: `rgb_out = rgb_in * 2^exposureStops`, `a_out = a_in`; if a source pixel is out of bounds it writes 0,0,0,0.
- CMake targets: `openfilm_core` (static lib), `test_core` (registered with CTest).

### Task 2: Metal kernel, MetalRenderer, GPU-vs-CPU harness

**Files:**
- Create: `src/metal/shader_types.h`, `src/metal/exposure.metal`, `src/metal/metal_renderer.h`, `src/metal/metal_renderer.mm`, `cmake/OpenFilmBundle.cmake` (metallib part)
- Modify: `CMakeLists.txt` (metallib target, `openfilm_metal` lib, `test_gpu`)
- Test: `tests/gpu/test_gpu_vs_cpu.mm`

**Interfaces:**
- Consumes: `ImageGeometry`, `RenderWindow`, `RenderParams`, `renderCpu` (Task 1).
- Produces:
  - `shader_types.h` (plain C, must compile in both MSL and C++):
    `typedef struct { int x1, y1, x2, y2; int rowFloats; } OFImageGeom;`
    `typedef struct { OFImageGeom src; OFImageGeom dst; int winX1, winY1, winX2, winY2; float gain; } OFExposureUniforms;`
    (`rowFloats = rowBytes / 4`. Resolve rows are always 4-byte aligned.)
  - `exposure.metal`: `kernel void exposure_kernel(device const float* src [[buffer(0)]], device float* dst [[buffer(1)]], constant OFExposureUniforms& u [[buffer(2)]], uint2 gid [[thread_position_in_grid]])`. Grid = window size. It guards `gid` against window size, maps to `x = winX1 + gid.x` and `y = winY1 + gid.y`, and uses the same semantics as `renderCpu`.
  - `class openfilm::MetalRenderer` in `metal_renderer.h`. The header compiles from plain C++, so it uses `void*` for Objective-C objects behind a pimpl. Members:
    - `explicit MetalRenderer(const std::string& metallibPath);`, which loads the library on the system default device
    - `bool isValid() const;`
    - `const std::string& error() const;`
    - `bool render(void* commandQueue, void* srcBuffer, const ImageGeometry& srcGeom, void* dstBuffer, const ImageGeometry& dstGeom, const RenderWindow& win, const RenderParams& p);`
    - `commandQueue` is an `id<MTLCommandQueue>` and the buffers are `id<MTLBuffer>`, all passed bridged. `render` commits without waiting, because Resolve synchronises.
    - Pipeline states are created on the queue's `device`, which may differ from the system default. Cache them per device, under a mutex, because Resolve renders from several threads.
- CMake: custom command `xcrun -sdk macosx metal -c src/metal/*.metal -o …air` then `xcrun -sdk macosx metallib … -o ${CMAKE_BINARY_DIR}/OpenFilm.metallib`; target `openfilm_metallib`; static lib `openfilm_metal` (links `-framework Metal -framework Foundation`, ARC on: `-fobjc-arc`); `test_gpu` gets compile definition `OPENFILM_METALLIB_PATH="${CMAKE_BINARY_DIR}/OpenFilm.metallib"`; `add_test(NAME gpu COMMAND test_gpu)`.

- [ ] **Step 1: Write the failing tests** in `tests/gpu/test_gpu_vs_cpu.mm`. Helper `runBoth(srcGeom, dstGeom, win, stops)`:
  - It fills src with a deterministic pseudo-random pattern in [−1, 100] (`std::mt19937` seed 42) and sets the padding to NaN.
  - It creates shared-storage `MTLBuffer`s, runs `MetalRenderer::render` on a fresh queue, and calls `waitUntilCompleted` on a final empty command buffer.
  - It runs `renderCpu` on host copies, then returns the max abs diff over every dst pixel, including those outside the window, which were prefilled with 7.0 in both.

  Test cases:
  - `TEST_CASE("gpu matches cpu: 1920x1080, +1.5 stops")` → max diff ≤ 1e-5 × max|value|.
  - `TEST_CASE("gpu matches cpu: odd sizes")`: 1×1 and 1921×1081 → same tolerance.
  - `TEST_CASE("gpu matches cpu: offset bounds, padded rows, sub-window")`: src bounds {10,20,330,260} with rowBytes = 320*16+64, dst the same bounds with tight rows, window {50,40,300,250}.
  - `TEST_CASE("invalid metallib path")`: `MetalRenderer("/nonexistent.metallib")` → `isValid()==false` and `error()` non-empty.

- [ ] **Step 2: Run to verify failure**
  Run: `cmake -S . -B build && cmake --build build --target test_gpu`
  Expected: build error, `metal_renderer.h` not found.

- [ ] **Step 4: Run to verify pass**
  Run: `cmake --build build && ctest --test-dir build --output-on-failure`
  Expected: `core` and `gpu` both pass.

- [ ] **Step 4: Implement the plugin**
  - `ofx_support` static lib compiles `external/openfx/Support/Library/*.cpp` with includes `external/openfx/include` and `external/openfx/Support/include`.
  - `openfilm_plugin.cpp`:
    - `OpenFilmFactory : OFX::PluginFactoryHelper` plus the `OFX::Plugin::getPluginIDs` registration.
    - `describe` sets the label, grouping, bit depth, contexts, `setSupportsMetalRender(true)` (or the `kOfxImageEffectPropMetalRenderSupported` = "true" property if the helper is absent), `setSupportsTiles(false)`, and `setSupportsMultiResolution(false)`.
    - `describeInContext` defines the clips and parameters.
    - `OpenFilmEffect::render`:
      1. Fetch src and dst images. Throw `kOfxStatErrImageFormat` unless both are float RGBA.
      2. Build `ImageGeometry` from `getBounds()`/`getRowBytes()`, a `RenderWindow` from `args.renderWindow`, and `RenderParams` from `exposure->getValueAtTime(args.time)`.
      3. If `args.isEnabledMetalRender`, call `MetalRenderer::render(args.pMetalCmdQ, src->getPixelData(), …, dst->getPixelData(), …)`. Under Metal, Resolve's pixel-data pointers are `id<MTLBuffer>`.
      4. Otherwise call `renderCpu`.
    - The `MetalRenderer` is created lazily, once per process, with a `std::once_flag`. Its metallib path comes from the bundle: `dladdr` on a local symbol gives `…/Contents/MacOS/OpenFilm.ofx`, then go `../Resources/OpenFilm.metallib`.
    - If `!isValid()`, call `setPersistentMessage(OFX::Message::eMessageError, "", "OpenFilm: GPU shaders failed to load: " + error())` and throw `kOfxStatFailed`.
  - `Info.plist.in`:
    - `CFBundleExecutable` = `OpenFilm.ofx`
    - `CFBundleIdentifier` = `org.openfilm.OpenFilm`
    - `CFBundlePackageType` = `BNDL`
    - `CFBundleShortVersionString` = `@PROJECT_VERSION@`
  - `OpenFilmBundle.cmake`: a `MODULE` library `OpenFilm` with `PREFIX ""`, `SUFFIX ".ofx"`, and `LIBRARY_OUTPUT_DIRECTORY` set to `${CMAKE_BINARY_DIR}/OpenFilm.ofx.bundle/Contents/MacOS`. A post-build step:
    - configures the plist into `Contents/`
    - copies `OpenFilm.metallib` into `Contents/Resources/`
    - runs `codesign --force --deep -s - OpenFilm.ofx.bundle`, an ad-hoc signature that Apple Silicon requires before Resolve will load it.

    Pass `-fvisibility=hidden` everywhere except the two exported OFX entry points; the Support lib already marks them `OfxExport`.

  Run: `cmake --build build && ctest --test-dir build --output-on-failure`
  Expected: `core`, `gpu`, `bundle` all pass. Also run `codesign -v build/OpenFilm.ofx.bundle`; expected: no output, exit code 0.
